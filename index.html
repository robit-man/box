01 / Machine

      

      

      Checking browser storage…
      

      

      
A new virtual disk is unformatted. Install Alpine with setup-alpine, then run Save disk and select Installed hard disk. Disk data is saved to this browser's IndexedDB only when you click Save disk. VM state files are separate from virtual disk files.

    

    

      
02 / Network

      

      

      
For apk, npm, git and agent APIs over HTTPS, select WISP with a reachable trusted wisps:// relay. The built-in Fetch mode does not provide full HTTPS/TCP. A static webpage cannot create unrestricted TCP sockets without a relay. Network settings take effect on boot.

    

    

      
03 / Install Node + npm

      
  1. Boot Alpine ISO. Log in as root (initially no password).
  2. Connect WISP networking; check ip addr. Run setup-alpine to install to sda using sys mode.
  3. Reboot from disk; save virtual disk after changes or before closing the tab.

      
apk update && apk add nodejs npm git curl ca-certificates

      
node -v && npm -v && git --version

      
Alpine 3.24 x86 has installable Node/npm packages, but emulated 32-bit x86 is slower than native and some native npm binaries/agent CLIs require x86-64.

    

    

      
04 / Agent workspace

      
Includes a small tool-calling Node agent source file. It runs inside the guest and can read/write files and execute commands in the guest only, via an OpenAI-compatible Chat Completions API.

      

      
mkdir -p /mnt/host /root/workspace; mount -t 9p -o trans=virtio,version=9p2000.L host9p /mnt/host; cp /mnt/host/agent.mjs /root/workspace/

      
cd /root/workspace && npm init -y && npm install openai

      
export OPENAI_API_KEY='…'; export OPENAI_MODEL='gpt-5.1'; node agent.mjs "inspect this project"

      
Set API credentials inside Linux, not in the web page. The starter grants the model shell execution inside the guest; use only in this isolated environment. 9p requires guest kernel support and an explicit mount.

    

    

      
05 / Export

      

      
Bundles emulator, firmware and the chosen boot image as base64 into one HTML file. Optionally bundles a saved disk image, if present. Large disk images may produce a very large HTML file. Network access for package installs still requires a WISP/WebSocket relay.

      
      
What is and isn't supported
Yes: real 32-bit Linux kernel, shell, on-disk files, Node/npm with network, git, scripts, and JS coding agents. No: native Docker, KVM, 64-bit Linux executables, GPU passthrough, direct arbitrary browser TCP, or guaranteed compatibility with packaged proprietary CLIs.
